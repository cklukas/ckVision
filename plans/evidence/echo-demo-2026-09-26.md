# Echo demo on real PTYs — macOS and Linux, 2026-09-26

This record is evidence for the ROADMAP M3 exit item "interactive echo demo on
macOS and Linux". The demo is `examples/echo` (`ckvision_echo`). Its behaviour
and its scripted, golden-pinned headless test are documented in
[example-apps.md](../../docs/example-apps.md#echo-examplesecho).

## What these runs are, and what they are not

Each run started the real `ckvision_echo` binary on a real pseudo-terminal
through `PosixTerminal`, in raw mode, on the alternate screen, with SGR mouse,
focus and bracketed-paste modes enabled by the program itself. A small Python
driver played the terminal. It forked the program onto a PTY, wrote the exact
byte sequences a host sends for each input, and resized the PTY with
`TIOCSWINSZ`. It kept every byte the program wrote, and read the transcript
the program appends with `ckvision_echo <file>`.

**A driven PTY session is not a person at a terminal.** No terminal emulator
turned physical keys, clicks or pastes into these bytes; the driver wrote them
directly. These runs therefore show what the macOS and Linux PTY layers and
ckVision's decoder and dispatch do with those bytes on each OS, end to end.
They do not show what a particular terminal emulator sends for a particular
physical key. The driver also answered none of the program's capability
probes, so both sessions stayed on the baseline profile. A hand run in a real
terminal remains the owner's to do. `ckvision_echo transcript.txt` records
such a run in the same form as the records below.

## What the demo printed

Both hosts printed the same 28 lines. The transcript files were identical, and
so were the complete output byte streams: 12,902 bytes each, compared with
`cmp`. The screen just before the quit chord, reconstructed from the output
bytes with a VT emulator (pyte), showed lines 1 to 27 under the header, at
120×40. Line 28 was recorded as the program quit.

```text

     2  resize  100x30
     3  focus   gained
     4  key     press   "a"  U+0061
     5  key     press   "é"  U+00E9
     6  key     press   Ctrl+"a"  U+0061
     7  key     press   Up
     8  key     press   Ctrl+Right
     9  key     press   F1
    10  key     press   F5

    12  key     press   Enter

    19  mouse   up      left        cell 12,5

    22  mouse   down    left        cell 4,4  Ctrl+Shift

    25  focus   lost

    27  resize  120x40
```

Every input reached the view once, decoded as sent. The lone Esc became `Esc`
only after the decoder's quiet deadline. SGR coordinates are 1-based on the
wire and 0-based in the event. The paste arrived as one event: paste
sanitization kept the tab and the line feed, and replaced the carriage return
with U+FFFD. The host focus reports were forwarded to the focused view. The PTY
resize was picked up through SIGWINCH and reached the view as its new size.
Tab and Shift+Tab stayed with focus traversal, which found only the echo view,
so no focus line followed them. The quit chord ended the program with exit
status 0 on both hosts.

No line reports a capability change. The program sent its capability probes
(OSC 10/11, DECRQM, DA1, XTSMGRAPHICS, XTWINOPS, the kitty keyboard query and
the pointer-shape query), and the driver answered none of them.

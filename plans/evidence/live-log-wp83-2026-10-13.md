# WP-83 installed clients and reference evidence — 2026-10-13

Implementation is complete; Windows and final release acceptance remain pending.
D-145 specifies SDK-only installation and public-header recipes. No prohibited
implementation source was read and no external dependency was introduced.

The Development component installs the SDK library/headers/CMake support and
three public client programs, preserving ordinary full-install scope. The
interactive file monitor composes shipped follower/filter/search/panel/controller
objects. Executable recipes prove append identity, structured metadata and an
actual asynchronous custom producer with explicit bounded loss. The real-file
contract validates native and polling observation, append, pause intake and
resume. Views die before borrowed models; services enclose sessions/wake targets;
no custom tailer, queue drain or filtering implementation was added.

The guide explains construction, source/permission choices, retention/overload,
rotation uncertainty, query publication, custom producers and performance tuning.
All live-log/continuous-pump declarations now have caller-facing comments;
**168 installed headers, 4228 public declarations, zero undocumented** pass the
unchanged API reference checker. The installed examples explicitly register
standard roles and install a theme, as the public Application contract requires.
A first executable run caught that omitted composition step; it was corrected
rather than suppressing the contract check.

**Installed clients compile with strict warnings and execute under ASan/UBSan on
macOS and Debian ARM64 Clang19**, using only the installed exported target and
headers. Both recipe and real-file contracts pass. Linux also enables leak
checks. Native/polling cases create only a uniquely named file under the caller's
explicit disposable scratch directory and remove it after service retirement.
The interactive client is compiled, not launched; native visual acceptance is
separate.

**Sixteen SVGs** are generated from the same application scenario builders as
pinned goldens. Capture requires exact golden equality, checks every decoded VT
cell against the composition's declared capability projection, then renders the
independent terminal decoder. The screenshot freshness gate reproduces exactly
sixteen byte-identical files. They are headless VT evidence, not actual windows.
All files parse as SVG with explicit view boxes.

The [JSON record](live-log-wp83-2026-10-13.json) retains build configuration,
source/output SHA-256, timestamps/durations, installed SDK/client identities,
figure fingerprints and current gate results. Mac uses selected mounted S8T;
Linux uses the owned shared PRO-BLADE workspace with explicit remote TMPDIR.
Initial installed Mac client execution/build took 26.92s, the comparable
increment 13.62s; Linux configure/install/client build/execute took 131.36s.
There is no identical cross-host baseline. Header reference edits rebuilt 35
Mac actions in 42.42s; the final one-header increment rebuilt/relinked its actual
dependents in 23.38s. Logs and unchanged fingerprints establish freshness;
loaded-host elapsed time is not runtime performance evidence.

Eleven focused Mac gates pass: installed clients, screenshot capture, 23 demo/
parser/replay cases, API comments/self-test, provenance/self-test, layer/self-test
and license/self-test. The Mac/Linux SDKs include unrelated in-progress completion
work excluded from this commit; they are not a clean committed-tree release proof.
Windows installed/native checks, final clean builds/full suites/fuzz/TSan/resource
stability, benchmark budgets and actual native-window/input/visibility/idle
acceptance carry into WP-84 under the owner's load-deferral instruction. WP-83
is gate pending, not Done.

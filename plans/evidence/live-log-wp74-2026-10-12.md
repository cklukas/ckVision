# WP-74 bounded model validation

LogModel implements a fixed payload arena, fixed record slots and bounded
reusable partial/metadata/UTF-8 staging. Appends, eviction, lookup and clear
allocate nothing after construction. Raw bytes are preserved separately from
safe display text; explicit multiline records retain LF separators. Sources,
generations and sequences provide stable identity across partial updates and
never rewind after clear.

Seventeen source/model unit cases pass with ASan/UBSan and strict warnings.
A separate allocation executable passes one case exercising first and repeated
appends, decoding, metadata, lookups, eviction and clear over 1000 iterations.
Nine final CTest gates pass: source, model, allocation, provenance/checker,
layer/checker and license/checker. The model suite includes an explicit record
state golden, exhaustive two-chunk splits plus byte-at-a-time decoding,
progress-overwrite splits and repeated arena wrap/eviction. Window/frame goldens
remain the view package's responsibility; these tests make no live UI claim.

Both executable/source fingerprints were checked after the final builds and
before commit; no inputs changed while building. Commands invoke Apple Clang
directly at nice 10; there is no compiler-cache wrapper. Build logs have zero
warnings. Larger elapsed times on this heavily loaded host were investigated
using the full compile commands, unchanged input hashes, clean logs and output
hash/mtime records; elapsed time is not freshness or performance evidence.
The isolated model baseline changes below reflect the recent same-target build,
not a library latency/throughput baseline. No application was launched.

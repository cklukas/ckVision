# WP-75 native file delivery validation

The native adapter implements macOS vnode/kqueue, Linux inotify and Windows
parent-directory notifications, regular-file identity/stat/range reads, explicit
polling fallback, monotonic request revisions and nonblocking session retirement.
All source I/O and handle cleanup run on prestarted owned workers. Request and
result slots are fixed; transfer copies only used bytes. Optional LogWake targets
notify readiness, first pending change and failure without per-line callbacks;
TerminalLogWake borrows a longer-lived terminal rather than an Application/view.
The scripted fixture can deliver delayed revisions, lost hints and identity
changes for deterministic follower tests.

The current wake-enabled code passes **32 cases on macOS and on the ckdev
Debian ARM64 VM**: 4 core contracts, 14 model, 12 scripted/native source, and
2 allocation cases. The first 30 run with ASan/UBSan; the allocation executable
is independent. The source tests cover bounded offsets/EOF, revision replacement,
append/truncate, pathname versus open-file rotation, missing/recreated/nonregular
files, explicit polling, capacity retirement/reuse, Unicode paths, access denial
and recovery, and readiness/coalesced-hint wakes. Steady native read/request/take
and model append/evict/lookup allocate nothing. Mac CTest passes **10/10**, including
both provenance gates, layer/license gates and their checker self-tests. VM CTest
passes **4/4** focused suites. No app or visual fix is claimed.

An earlier rpi4 GCC 14 UBSan run passed 31 cases before the optional wake target
was added; it is historical precursor evidence. ASan did not start there with
GCC 14 or Clang 19, including an empty-program probe. The process had unlimited
virtual-memory limit, 7.3 GB available physical memory, and no seccomp filters;
its process mappings use the low ARM64 address range. The startup failure matches
[Debian bug 1115578](https://lists.debian.org/debian-gcc/2025/09/msg00172.html).
No Raspberry Pi ASan pass is claimed. Linux ASan acceptance for this package
uses the existing compatible Debian VM instead; no kernel/runtime setting was
changed to hide the failure.

Temporary Mac build/test data uses `/Volumes/S8T/tmp/ckvision-live-logs-3sp5hyr5`.
The existing VM exports PRO-BLADE/tmp but not S8T, so its uniquely owned source,
compiler scratch, binaries and fixture files use the permitted host share
`/Volumes/PRO-BLADE/tmp/ckvision-live-log-vm-khjaku8v`. Existing VM disks/configuration and unrelated completion
work were preserved. Direct one-process compiler commands use strict warnings
as errors and no compiler-cache wrapper. Source/output hashes were verified after
all tests; no actual app was launched. Different elapsed times were checked
against command/input scope and clean logs under changing host load; they are
not latency/throughput measurements. First same-platform native builds establish
comparable build history, never an invented performance baseline.

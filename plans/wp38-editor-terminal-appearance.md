graphics-profile matrix. It inventories current executable and visual evidence;
it does not promote the full appearance matrix or WP-38 to Done. The four
built-in schemes are classic, dark, light, and mono. Paths below name
checked-in artifacts; executable producers are identified where a capture
alone would otherwise be weak evidence.

The existing `generated_golden_bytes` gate covers the named checked-in files,
not an automatically generated Cartesian product of every state and scheme.
The broader widget/chrome appearance rows in [WP-38](corrective-assurance.md#wp-38--golden-script-reference-and-release-gate-closure)
remain outside this slice. This audit makes the unfilled combinations explicit
before adding captures; it is not a reason to rerun completed live Windows
scenarios without a relevant code change.

Runtime scheme switching initially left retained desktop/window surfaces in
the previous colors. `Application::set_theme()` now invalidates the subtree;
the four generated contained-scene dumps differ by scheme while the decoded
Sixel plane remains the same image. The no-graphics profile has a transparent
pixel plane under every scheme.

At `4b41188`, the full macOS build and CTest suite passed 177/177;
`generated_golden_bytes` covered the current 79-file manifest. Linux Release
and Windows ARM64 Release built both runnable examples and the terminal/editor
generators from the current source. Each host regenerated 63 terminal graphics
files and six editor files with no mismatch against the pinned bytes. The
Windows source was staged from a SHA-256-verified `b3a54c1` archive plus the
two `4b41188` source changes, whose destination hashes were checked before
the build. This establishes three-host byte identity for the 69-file
editor/terminal slice. The five other portable generators were then built on
Linux and Windows ARM64. The complete current 79-file manifest is **Done**:
79/79 generated bytes matched the pinned files on macOS, Linux, and Windows
ARM64. macOS and Linux produced the same manifest SHA-256
`0fc779d931956f12a8b94011365c2b29cf82a38837babf54fda732f3081e0ff8`;
Windows checked each generated file hash against its pinned golden artifact.

The Terminal and Editor examples now expose live scheme changes in their View
menus. The terminal's two-window command path and the editor's preserved
search selection/caret path are scripted. Remaining state × scheme/profile
combinations and WP-38 release gates stay Open.

Live Editor and Terminal View menus now expose the selected scheme as a radio
mark. The menu model reads its mark provider at draw time, so switching schemes
updates the same menu items without reconstructing the menu. The focused menu,
Editor, and Terminal command-path checks pass in the 177-test macOS Release
suite; this is a usability feature within the appearance slice, not closure
of the remaining state × scheme/profile matrix.
